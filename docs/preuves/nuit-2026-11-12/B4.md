# B4 — N4 page téléphone WebRTC, code et essai local

Nuit autonome du 12/11/2026, conducteur B, branche `nuit/B4` partie de `origin/main@9480c69`. Code : commit `eb7715a`.

Périmètre livré : le code et l'essai local. L'exposition, autorisée, **n'est pas faite** : motif plus bas.

## Livré

- **Commande** `voice-realtime telephone`. Un seul port sert la page en HTTP et l'appel en WebSocket (`/ws`), avec la bibliothèque `websockets` déjà présente : aucune nouvelle dépendance.
- **`voice_realtime/telephone/pont.py`** (`PontAppel`) relie un appel à n'importe quel fournisseur du protocole `providers` (mode chaîne, Gemini Live, OpenAI Realtime) :
  - flux : trames PCM16 entrantes, audio sortant en binaire, transcriptions, coupure de parole (`interrompu` : la page vide sa lecture) ;
  - outils : exécutés comme dans `talk`, avec refus si `demander_avant_agir` est actif sans interface ; la page ne reçoit que le nom de l'outil et son succès, jamais ses arguments ni son résultat ;
  - fins d'appel : mot d'arrêt (énoncé final, partiels cumulés ou texte saisi), plafonds de durée et de coût (`CostTracker`), muet, texte saisi, erreurs du fournisseur sans détail transmis à la page.
- **`voice_realtime/telephone/serveur.py`** (`ServeurTelephone`) :
  - un seul appel à la fois (réponse `occupe` au second), un fournisseur neuf par appel ;
  - en-têtes : CSP stricte sans `unsafe`, `Permissions-Policy: microphone=(self)`, `no-store`, `nosniff`, `DENY` ;
  - verrous locaux :
    1. écoute sur `127.0.0.1` ;
    2. liste fermée d'hôtes, qui empêche le rattachement DNS : réponse 421 ;
    3. `Origin` du WebSocket égal à l'hôte servi ou à un nom public déclaré ;
    4. dès qu'un nom public est déclaré : vérification du jeton Access (`acces.py` : RS256, émetteur, audience, expiration, adresse ; JWKS relu au plus une fois par minute à la rotation), ou jeton local `Authorization: Bearer` comparé en temps constant (fichier 600). Ce second mode correspond au relais du Worker, sur le modèle de l'écran O5.
  - `--prefixe` sert la page sous un chemin public.
- **`voice_realtime/telephone/configuration.py`** :
  - aucun fournisseur par défaut : `--provider` est obligatoire ;
  - outils par défaut : les 5 de l'orchestrateur ;
  - consigne vocale propre au téléphone : réponses orales courtes, données des sessions non fiables, relecture et confirmation en deux temps de `send_instruction`, sans jamais confirmer à la place de Stéphane ;
  - clés nommées quand elles manquent, jamais affichées.
- **Page** (`static/`), mobile d'abord, en français, sans ressource externe et uniquement en adresses relatives :
  - micro : `getUserMedia` avec annulation d'écho, réduction de bruit et gain automatique ;
  - worklet de capture : filtre moyenneur, rééchantillonnage vers la fréquence annoncée par le serveur, trames de 20 ms ;
  - worklet de lecture : file vidée d'un coup sur coupure ;
  - interface : bouton Appeler / Raccrocher, muet, niveaux, transcription (en `textContent`, jamais en HTML), saisie de secours, Wake Lock, message clair hors HTTPS.
- **`scripts/essai_telephone_chrome.py`** : essai réel dans Chrome sans interface, décrit ci-dessous.
- **Tests** : 66 nouveaux (`tests/test_telephone_*.py`, faux partagés dans `tests/faux_telephone.py`). README complété.

- **Pont** (faux fournisseur) :
  - ouverture : fréquences, outils, salutation ;
  - audio : transmis, sauf en muet ; trames impaires ou trop grandes refusées ;
  - traduction des événements ; mot d'arrêt final, sur partiels cumulés (et remis à zéro quand le modèle parle) et saisi ;
  - outil exécuté, ou refusé et en échec (outil inconnu, exception, demande préalable) ;
  - arrêts : erreur du fournisseur, flux fermé, connexion impossible, durée maximale, coût maximal, page coupée pendant l'audio ;
  - avec le vrai `ChainProvider` sur `deux_phrases.wav` en trames de 20 ms : deux énoncés, puis un tour avec outil.
- **Serveur** (réel, sur la boucle locale) :
  - page et ressources : types MIME et en-têtes ; `/sante` sans donnée de session ;
  - refus : 404 hors routes et traversée, 421 sur hôte inconnu, 403 sur origine absente, `null` ou étrangère ;

  - fermeture de la page vaut fin d'appel ; second appel `occupe`, puis nouvel appel accepté ;
  - Access : 403 sans jeton ou pour une autre adresse, 200 et WebSocket avec un jeton signé ;
  - mode relais (Host réécrit en `127.0.0.1`, origine publique, préfixe `/voix`) : 401 sans jeton local ou avec un faux, 200 avec, 404 hors préfixe, 403 sur origine étrangère même avec le jeton ;

## Non prouvé, non fait

- **Exposition non faite** (autorisation 1), pour quatre raisons :
  1. Le jeton `wrangler` n'a pas la portée Access, comme l'a constaté A4. Aucune application Access ne peut donc être créée pour un nom ou un chemin nouveau.
  2. Le seul chemin déjà protégé est `/authorize/…` sur le Worker du Cockpit (modèle de l'écran O5). Ce relais n'accepte que GET et HEAD : il faut lui ajouter le passage de l'upgrade WebSocket, qui est du code dans le dépôt du Cockpit (worktree du conducteur A) avec un nouveau déploiement. Cela sort du périmètre de B, sans compter le risque de conflit avec A11, durcissement du même Worker.
  3. Un service exposé cette nuit n'aurait aucun fournisseur utilisable : les API payantes sont interdites et le modèle whisper local est tronqué.
  4. La connexion Access réelle demande la double authentification de Stéphane.

  Côté ce dépôt, tout est prêt : `--prefixe /voix --jeton-fichier <fichier 600> --nom-public jarvis.dufresne-ia.com`, sur le modèle d'O5. Il reste, dans le Cockpit :
  - la route `/authorize/voix/` du Worker, avec relais WebSocket et jeton local ;
  - la règle de tunnel `^/voix/(…)?$` vers `127.0.0.1:7720` avec `httpHostHeader` ;
  - un espace cmux de service.

  Autre voie : Stéphane ajoute un nom d'hôte et une application Access dans le tableau de bord, et le serveur vérifie lui-même le jeton (`--access-*`).
- **Aucun essai sur un vrai téléphone.** Non éprouvés : Safari sur iOS (qui coupe le micro quand l'écran se verrouille ; Wake Lock demandé), l'annulation d'écho du navigateur en haut-parleur, le réseau mobile.
- **Aucun fournisseur réel :** ni Gemini, ni OpenAI, ni modèle par API, ni whisper.cpp. La transcription et le modèle de l'essai sont scriptés.
- **WebRTC partiel, par choix :** pas de `RTCPeerConnection`. Le transport est un WebSocket en PCM16 (environ 256 kbit/s montants à 16 kHz), sans Opus ni gigue adaptative. Raison : seul un WebSocket traverse Access et le tunnel HTTP ; un flux UDP exigerait un serveur TURN et contournerait Access (décision consignée dans la roadmap).
- Le micro simulé de Chrome ne lit le fichier qu'avec `--disable-features=AudioServiceSandbox` (sous macOS, Chrome 157) ; l'option ne concerne que l'essai.
